# Local-first Web 第一階段：本機帳本儲存底座

> **狀態：0.13.0 已實作本文件的合成資料儲存底座；以下「已核對現況」為 0.12.2 實作前基準。日期：2026-09-30。**
>
> 本階段只使用合成資料；完成後仍不得輸入真實帳目或停用 Python Web。

## 目標與產品邊界

正式產品將從固定、可信的 HTTPS 網址取得靜態 Web／PWA 程式，原始帳本預設只存在使用者自己的裝置。記帳不需帳號；不同裝置不暗中同步，只能由使用者主動備份、確認並還原。程式主機可能看到一般連線資訊，不宣稱完全沒有網路或中繼資訊。

本階段先把現有 `local-first/` 合成驗證頁的儲存底座做成可承受長期資料的結構：無損升級、原子操作、完整備份、可量測容量與失敗保護。其後才逐項搬入 Python Web 現有功能，最後才處理固定來源與真實資料切換。收入分配與其他新功能不插入這次移植。

## 已核對現況（0.12.2 實作前基準）

- `local-first/ledger.mjs` 用 IndexedDB 版本 1 的單一 `ledger` store，以 `local-test-owner` 和 `created` 保存整本合成帳及標記。每次寫入載入、驗證並覆寫整本帳；內部狀態版本為 2。
- 現有測試上限是 200 筆消費（含撤銷）及 1000 筆操作。完整 JSON v1 另外有 16 MiB、總列數 100000、深度、文字及整數界限；Python 與瀏覽器各有驗證器。
- 完整備份保存九類資料、精確 cents、關聯、歷史快照及操作順序。空白還原有交易內二次檢查。Service Worker 只快取程式，不保存帳目。
- 本機頁目前只有手動消費新增、更改、軟刪除、清單與備份／還原；搜尋、月曆、預算、固定支出及分析等 Python Web 功能不在本階段實作。

## 儲存配置與升級

沿用合成測試資料庫名稱，把 IndexedDB schema 升至版本 2。用原生 stores 分別保存 `expenses`、`actions`、`categories`、`payment_sources`、`budgets`、`recurring_rules`、`recurring_versions`、`shortcuts`、`settings`，再用最小 `meta` store 保存建立標記與操作順序計數。不增加 Repository、ORM、同步服務或第二套規則。

消費、付款方式、規則、捷徑和操作沿用原字串 ID；分類用名稱，預算用 `[month, category]`，規則版本用 `[recurring_id, effective_month]`，設定只有一筆。操作另有內部單調順序，不能按隨機字串 ID 猜最新操作。九類資料保留原陣列順序所需的內部序位；它不進 JSON v1。只增加現有清單／日期操作必要的索引，不為尚未實作的泛用查詢預建索引。

版本 1 → 2：先用現有規則驗證舊合成狀態，再在單一 `versionchange` 交易中建立及填入新 stores、檢查筆數、引用、順序及備份等價，成功後才移除舊 store。任一步失敗即中止升級，不留半套資料；不能自動清除、猜測修復或降版。另一頁籤持有舊版本時，舊連線依 `versionchange` 關閉；升級被阻擋時只顯示固定安全提示。空白資料庫直接建立版本 2；損壞、未知版本及未來版本停止寫入並保留資料。未修改的合法舊合成帳本升級前後須能匯出逐位元組相同的 JSON v1。

從 localhost 換到 HTTPS 網址是跨來源搬移，不會自動共用 IndexedDB；只允許使用者主動備份並還原到完全空白的新來源。本階段不部署正式網址、不讀取正式 Python `data.db`。

## 寫入、備份與容量

新增、更改與軟刪除都在同一 `readwrite` 交易中重新讀取、比較 revision，並一起保存帳目、操作紀錄與順序；只在交易 `complete` 後回報成功。多分頁沿用 IndexedDB 交易與 revision，不另造全域鎖。配額不足、舊 revision、重複操作或中途失敗不能留下部分結果。

匯出在同一 `readonly` 快照讀取九類資料，沿現有 JSON v1 欄位與順序完整輸出，不補建預設或自動入帳。還原先完整驗證，再於單一寫入交易重新確認所有 stores 完全空白；不覆蓋、不合併。保留付款名稱快照、軟刪除、自動來源、歷史版本及操作 `before`。

移除 200／1000 測試專用筆數上限，但**任何已提交狀態都必須能以支援的完整備份格式匯出**。JSON v1 的位元組安全上限在 Python 與瀏覽器兩端同步提高至 64 MiB；版本號與欄位不變，100000 總列及其他驗證界限不放寬。會使完整備份超限的寫入須在提交前拒絕，保留既有可匯出帳本。舊版 Python／瀏覽器仍只認 16 MiB，故新大檔不保證能回讀至舊版；舊的小檔仍可讀。是否以整份計算或精確增量計數實作，由實測效能決定，但結果與邊界必須一致。

至少用 20000 筆消費及 50000 筆操作的合成帳本測試寫入、清單、匯出、空白還原及再匯出；記錄實際裝置／瀏覽器、資料大小、耗時與故障。這是本階段測試門檻，不代表所有手機或任意資料量都已驗證。若此樣本超過 64 MiB，或測試裝置不能完整往返，不能宣稱達標，須先修訂方案。

## 安全、排除項目與驗收

表單、匯入 JSON 及既存 IndexedDB 均不可信；沿用完整驗證、精確金額、文字安全呈現、固定錯誤訊息及引用檢查。不得把帳目、備份、憑證或個資寫進 URL、log、前端 bundle、靜態快取或第三方服務。本機頁沒有 OAuth 或網路寫入路由，不照搬伺服器 CSRF，但不削弱來源隔離、交易與 revision。

本階段不加入新依賴、帳號、雲端、同步、正式 HTTPS 部署、加密備份、Python Web／Discord 功能、收入、投資、多幣別或 App 包裝。未加密 JSON 仍只用於合成資料；正式使用之前另須可信來源、備份保護與復原、完整功能對照、正式搬移與實機驗證。

實作計畫必須先補會失敗的測試，至少覆蓋：舊版及空白升級、損壞／未知版本、升級中止與阻擋、兩頁競態、舊 revision、配額和中途失敗回滾、極端／惡意輸入、16／64 MiB 邊界、非空／重複還原、大量資料往返、離線冷啟動與更新失敗。另跑 Python 隔離、Node、實際瀏覽器、Ruff、JS 語法、差異及文件檢查。只回報實際跑過的項目與環境，不把合成結果說成正式帳本驗證。

交付時按 `AGENTS.md` 同步繁體中文 CHANGELOG 與 README，列出版本、容量量測、未驗證事項及仍不得輸入真實帳目的原因。0.13.0 的實作、實測與剩餘限制見 [CHANGELOG](../../../CHANGELOG.md) 及 [本機驗證文件](../../local-first-browser-validation.md)；本規格不是正式資料可用的核准。
